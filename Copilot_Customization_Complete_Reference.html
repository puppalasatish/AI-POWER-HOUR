When Does Each File Activate?

Understanding the activation model is the key to using Copilot customization effectively.

🟢 Always Active — Every Chat Interaction

These fire on every single chat message and agent interaction. You cannot disable them.

📋 copilot-instructions.md

Project knowledge loaded before every response. Architecture, tech stack, conventions, build commands.

  • Loaded in chat, agent mode, code review
  • Every agent inherits this context
  • NOT used for inline ghost-text suggestions

🤖 hooks/*.json

Deterministic shell commands that fire on lifecycle events. Not AI — pure code execution.

  • post-edit-lint.json → runs after every file edit
  • pre-execute-warning.json → runs before terminal commands
  • Cannot be skipped — guaranteed enforcement
🔵 Auto-Active — File Pattern Match

Loaded automatically when you have a matching file open. You don't invoke them — they watch what you're editing.

🐍 python.instructions.md

Activates when any .py file is in context

  • applyTo: "**/*.py"
  • Type hints, docstrings, exception handling rules

🌐 api-routes.instructions.md

Activates for API route files

  • applyTo: "src/api/**/*.py"
  • REST conventions, status codes, error responses

🧪 testing.instructions.md

Activates for test files

  • applyTo: "tests/**/*.py"
  • AAA pattern, naming, fixtures, coverage rules

🗄️ migrations.instructions.md

Activates for migration files

  • applyTo: "migrations/**/*.py"
  • Alembic conventions, rollback safety

📐 schemas.instructions.md

Activates for Pydantic schemas

  • applyTo: "src/schemas/**/*.py"
  • Validation patterns, field naming conventions
🟣 On-Demand — Agent Picker / @mention

You manually select these from the agent picker or type @name. Each has different tool permissions.

🛡️ @security-reviewer

Read-only security audit

  • Tools: read, search only — cannot edit
  • OWASP Top 10, SQL injection, auth checks

🗃️ @db-admin

Database schema specialist

  • Indexes, relationships, migration advice
  • Can read and write files

🧪 @test-engineer

Test writing specialist

  • Generates comprehensive test suites
  • Coverage analysis, edge case detection

🎨 @api-designer

API design reviewer

  • REST best practices, consistency checks
  • Schema validation, versioning advice

🔍 @code-explorer

Read-only codebase Q&A

  • Tools: read, search only — safe for anyone
  • Explains code, traces data flow

Copilot Best Practices

Search for any topic — commands, tips, and workflows to get the most out of GitHub Copilot.

🔍
CHATNAVIGATION

🔍 Use @workspace for Codebase Questions

Copilot searches your entire indexed codebase and pulls relevant files into context. No need to manually attach files.

@workspace explain the authentication flow📋
@workspace where is the database connection configured?📋
@workspace list all API endpoints and their HTTP methods📋
CHATEDIT

📎 Use #file: for Targeted Context

Attach specific files when you know exactly which ones are relevant. More precise than @workspace for focused tasks.

#file:src/services/config_service.py add caching logic📋
#file:src/models/config.py #file:src/schemas/config.py add a new field📋
AGENT MODE

🤖 Agent Mode for Multi-File Tasks

Agent mode can read, write, create files, and run terminal commands. Use it for tasks that span multiple files.

Add a new "tags" field to the config model, schema, repo, service, and API layer📋

Tip: Agent mode reads your copilot-instructions.md automatically — so it follows your conventions.

INLINE

👻 Accept Inline Suggestions Smartly

Copilot shows gray ghost text as you type. These use your current file and open tabs as context (NOT copilot-instructions.md).

Tab → accept full suggestion📋
Ctrl+→ → accept word by word📋
Alt+] → next suggestion / Alt+[ → previous📋
DEBUG

🔧 Use /fix for Quick Bug Fixes

Select broken code, type /fix, and Copilot analyzes the error and suggests a fix in context.

/fix — with error code selected📋
@workspace /fix the TypeError in payment_service.py📋
UNDERSTAND

💡 Use /explain for Code Understanding

Select any code block and type /explain. Great for onboarding or understanding legacy code.

/explain — with complex function selected📋
@workspace /explain how the encryption module works📋
TESTING

🧪 Use /tests for Test Generation

Select a function or open a file, then type /tests. Copilot generates test cases following your testing.instructions.md.

/tests — with source file open📋
@workspace generate integration tests for the config API📋
DOCS

📝 Use /doc for Documentation

Select a function and type /doc. Generates docstrings matching your configured style (Google, NumPy, etc.).

/doc — with function selected📋
TERMINAL

💻 Copilot in the Terminal

Use Ctrl+I in the terminal to ask Copilot for shell commands. It knows your OS and shell type.

Ctrl+I → "find all Python files with TODO comments"📋
Ctrl+I → "run pytest with coverage for the config module"📋
GIT

✨ Auto-Generate Commit Messages

Click the sparkle icon ✨ in the Source Control panel. Copilot reads your diff and writes a conventional commit message.

✨ icon in Source Control → auto-generates commit message📋
REFACTOR

✏️ Copilot-Assisted Rename

When you F2 rename a symbol, Copilot suggests smart names based on context and usage patterns.

F2 on a symbol → Copilot suggests contextual names📋
REVIEW

👁️ Code Review with Copilot

Use a custom agent or prompt to get structured code reviews covering security, performance, and conventions.

@security-reviewer review the payment service📋
/code-review — with changed files open📋
PERFORMANCE

⚡ Ask About Performance Issues

Copilot can identify N+1 queries, missing indexes, unnecessary loops, and suggest optimizations.

@workspace are there any N+1 query problems in the repos?📋

📂 Provide Rich Context

The more relevant context you give, the better the output. Combine @workspace, #file:, and open tabs.

Tip: Copilot also reads all currently open editor tabs as context.

How Copilot "Sees" Your Code

▼

Copilot doesn't read your entire repo every time. Here's what it actually sees:

1. Active file — the file you're editing (full content)

2. Open tabs — other files open in the editor (sampled)

3. copilot-instructions.md — always injected into the prompt

4. Matching *.instructions.md — if applyTo pattern matches

5. @workspace index — semantic search over workspace-chunks.db

6. #file: attachments — files you explicitly attach

Important: Copilot does NOT read all 10,000 files. It samples strategically. That's why copilot-instructions.md is so powerful — it's the only file guaranteed to always be included.
💬

Chat Modes: Ask vs Edit vs Agent

▼

Ask Mode — Read-only Q&A. Great for understanding code, getting explanations, learning. Copilot cannot modify files.

Edit Mode — Copilot can edit the files you specify. You review changes before accepting. Controlled, predictable.

Agent Mode — Full autonomy. Copilot can read, write, create, delete files, and run terminal commands. Follows your copilot-instructions.md for conventions.

When to use which:
• Exploring/learning → Ask
• Changing 1-2 files → Edit
• Multi-file feature work → Agent

VS Code Settings That Matter

▼

Key settings to configure in VS Code:

github.copilot.enable — Enable/disable per language

github.copilot.chat.localeOverride — Response language

chat.agent.enabled — Enable Agent mode

chat.includeApplyingInstructions — Enable pattern-based custom instructions

Must enable: chat.includeApplyingInstructions must be true for your .github/instructions files to auto-apply. Check this first if customizations aren't loading.

Security & Privacy to Know

▼

What Copilot sends: Your current file, open tabs context, instructions, and your prompt — sent to GitHub's AI service.

Business plan: Your code is NOT used for training. Prompts are NOT retained by GitHub beyond the session.

Telemetry: Usage metrics are collected (can be disabled in settings). Code snippets are not stored.

Never put secrets in instructions files. They are committed to Git. Use environment variables and reference them by name, not value.
Safe example: "Database connection uses the DATABASE_URL environment variable" — NOT the actual connection string.
🚫

Common Mistakes to Avoid

▼

❌ Dumping entire repo as context — Copilot has a token limit. Give targeted context, not everything.

❌ Vague prompts — "Make this better" → bad. "Add input validation for the email field using Pydantic" → good.

❌ Not reviewing output — Copilot is probabilistic. Always review generated code before accepting.

❌ Expecting 100% compliance — Instructions are guidance (~90-95%). Use hooks for guaranteed enforcement.

❌ Putting secrets in .md files — These are committed to Git. Never put API keys, passwords, or tokens.

❌ Ignoring open tabs — Copilot reads open tabs as context. Close irrelevant files to reduce noise.

Golden rule: Treat Copilot like a very fast junior developer who knows everything but needs clear, specific instructions.
📊

Instructions vs Hooks — The Key Difference

▼

Instructions = guidance for the AI model. Probabilistic. Copilot follows them ~90-95% of the time.

Hooks = shell commands that execute automatically. Deterministic. They run 100% of the time. No AI involved.

Example: "Always format with ruff" in instructions → Copilot MIGHT format. ruff check --fix in a hook → ruff WILL run, every time.

Strategy: Use instructions for patterns and conventions. Use hooks for enforcement and compliance. Together they cover ~100% of your needs.
