Section 01

copilot-instructions.md

The always-on brain — project knowledge loaded on every single interaction

📋
Think of it as: A sticky note permanently glued to Copilot's forehead. It reads it before EVERY conversation. You never call it. It's always there. There is no way to turn it off.
⚡ Always loaded — every interaction 📝 Inline suggestions too 🤖 Every agent gets it
Example 1 You ask Copilot to add a function — WITH instructions file ▼

You type: "Add a new function to process payments"

What Copilot actually receives (behind the scenes)
📋 SYSTEM — copilot-instructions.md (always loaded)
"This project uses Python 3.12, FastAPI..."
"Always use async def for I/O functions..."
"Never use raw SQL, use SQLAlchemy ORM..."
▼
👤 YOUR MESSAGE
"Add a new function to process payments"
▼
✅ RESULT
Copilot writes an async FastAPI function with SQLAlchemy ORM — because instructions told it your stack
Example 2 Same question — WITHOUT instructions file (the contrast) ▼
Without instructions — Copilot is blind
⚠️ SYSTEM — nothing (no copilot-instructions.md)
(Copilot has no idea about your project)
▼
👤 YOUR MESSAGE
"Add a new function to process payments"
▼
❌ RESULT
Copilot might write Flask, Django, or even Node.js — it's guessing because it doesn't know your project
Example 3 Even inline ghost-text suggestions are influenced by it ▼

You're typing code in the editor. Copilot's gray ghost text appears as you type. That suggestion was ALSO influenced by copilot-instructions.md.

You didn't open chat. You didn't ask for anything. It just knows your project rules and applies them to every single suggestion.

This is why it's the most important file — it influences EVERYTHING Copilot does.

Section 02

*.instructions.md

Smart rulebooks that automatically load based on what file you're editing

📚
Think of it as: A smart assistant who pulls the right reference book off the shelf ONLY when you need it. Working on Python? Python rulebook appears. Working on tests? Testing rulebook appears. You never ask — it just watches what file you're editing.
🔄 Auto-loads when file pattern matches 🧠 Also auto-detects by description keywords 📎 Can manually attach via "Add Context"
🎯
Mode A — Auto-Load (applyTo)
  • Uses applyTo: "**/*.py" in YAML frontmatter
  • Loads automatically when a matching file is in context
  • Unloads when you close that file
  • Multiple instruction files can match simultaneously
🧠
Mode B — On-Demand (description)
  • Uses description: "Use when writing migrations..."
  • No applyTo — Copilot reads description and decides if relevant
  • Loads when your QUESTION matches the description keywords
  • More flexible but less predictable than applyTo
Example 1 Editing a Python file — python.instructions.md auto-loads ▼

You open src/services/payment.py and ask: "Add error handling here"

Two instruction files loaded — you did nothing
📋 copilot-instructions.md ← always
"This project uses Python 3.12, FastAPI..."
📚 python.instructions.md ← auto-loaded (*.py matches)
"Use type hints on all functions..."
"Catch specific exceptions, never bare except:"
"Use Google-style docstrings..."
▼
👤 YOUR MESSAGE
"Add error handling here"
▼
✅ RESULT
Copilot writes specific exception handling with type hints and Google docstrings — because both instruction files told it your Python rules
Example 2 Switch to test file — BOTH python + testing instructions load ▼

You switch to tests/test_payment.py — now TWO instruction files match:

📋 copilot-instructions.md ← always
📚 python.instructions.md ← matches **/*.py
📚 testing.instructions.md ← matches tests/**
"Follow AAA pattern: Arrange → Act → Assert"
"Name: test_<action>_<scenario>_<expected>"
▼
✅ Multiple instruction files combine!
Python rules + testing rules both active — Copilot generates tests with type hints AND proper naming AND AAA pattern
Example 3 On-demand: you ask about migrations — instruction auto-detects from keywords ▼

You have migrations.instructions.md with no applyTo, just:

description: "Use when writing database migrations, schema changes, or Alembic operations"

You ask: "How do I add a new column to the users table?"

Copilot reads descriptions of all instruction files → "schema changes" in your question matches the description → loads it automatically without you doing anything.

Section 03

*.agent.md

Specialized experts you hire by name — each with different permissions

👨‍⚕️
Think of it as: Different experts sitting in a room — a security expert, a database expert, a testing expert. They sit quietly until YOU call one by name. Each expert has different tools they're allowed to use — the security reviewer can only READ code (can't change it), while the test engineer can read AND write.
🖱️ You select from agent picker 💬 You type @agent-name in chat 🤖 Another agent can auto-delegate to it
Example 1 You manually select @security-reviewer — restricted to read-only ▼

You click agent picker → select @security-reviewer → ask: "Review the payment service"

Agent loaded with restricted tools
📋 copilot-instructions.md ← always
👨‍⚕️ security-reviewer.agent.md ← you selected it
"You are a Security Reviewer..."
"Focus on OWASP Top 10, SQL injection..."
"DO NOT modify any files"
tools: [read, search] — CAN'T EDIT!
▼
👤 YOUR MESSAGE
"Review the payment service"
▼
✅ RESULT
Gets a focused security audit report. The agent literally CANNOT edit your files — it only has read + search tools. Safe by design.
Example 2 Same question without any agent — generic, unfocused result ▼
📋 copilot-instructions.md ← always
🤖 Default agent — has ALL tools, no specialization
▼
⚠️ RESULT
Generic review. Might try to edit files, might miss security-specific issues. No focused persona. No tool restrictions.
Example 3 Auto-delegation: parent agent delegates to sub-agent ▼

You're using the default agent and ask: "Is there a SQL injection risk in the login endpoint?"

🔄 AUTO-DELEGATION FLOW
1. Default agent sees "SQL injection" in your question
2. Reads @security-reviewer's description: "Use when reviewing code for security vulnerabilities..."
3. Keywords match → delegates to @security-reviewer automatically
4. Security reviewer runs in isolation → returns findings
5. Default agent presents the results to you

You didn't select any agent — but the right specialist was called anyway because the description keywords matched.

Section 04

SKILL.md

Recipe cards with actual ingredients — multi-step workflows with bundled scripts

🍳
Think of it as: A recipe card with actual ingredients attached. Not just instructions — but the actual scripts, templates, and files needed to complete a complex multi-step task. You type / and pick a recipe from the menu.
⌨️ Type / in chat → pick /skill-name 🧠 Can auto-detect from description keywords
1️⃣
Stage 1 — Discovery
  • Copilot reads ONLY name + description (~100 tokens)
  • Decides: "Is this relevant to what the user asked?"
  • Very lightweight — doesn't load anything yet
2️⃣
Stage 2 — Instructions
  • If relevant, loads the full SKILL.md body
  • Step-by-step procedure, rules, approach
  • Up to ~5000 tokens of instructions
3️⃣
Stage 3 — Resources
  • Loads referenced files: ./scripts/deploy.sh
  • Templates, reference docs, config files
  • Only when the procedure says to use them
Example 1 You type /deploy-staging — full workflow executes ▼
Skill loaded with bundled script
📋 copilot-instructions.md ← always
🍳 deploy-staging/SKILL.md ← you typed /deploy-staging
"1. Run pytest first — never deploy without passing tests"
"2. Build Docker image..."
"3. Run Alembic migrations..."
"4. Execute ./scripts/deploy.sh staging"
"5. Verify health check at /health"
▼
✅ RESULT
Copilot walks through ALL steps — runs tests, builds Docker, runs the actual deploy.sh script, checks health endpoint. Complete multi-step workflow.
Example 2 Auto-detection: you mention "deploy" without typing / ▼

You DON'T type /deploy-staging. You just say: "I need to deploy the app to staging"

Copilot reads all skill descriptions → finds deploy-staging with "Deploy ConfigTool to staging environment. Use when deploying, releasing..." → keywords "deploy" + "staging" match → loads the skill automatically.

The slash command is the SURE way. But smart description keywords also work.

Section 05

*.prompt.md

Pre-written requests you saved — speed-dial for repeated AI tasks

⚡
Think of it as: A pre-filled form you hand to Copilot. "Generate tests for this code" — but with ALL your specific requirements pre-written so you don't type them every time. One task, one shot, done. Like a speed-dial for AI tasks.
⌨️ Type / in chat → pick /prompt-name 🎮 Command Palette: "Chat: Run Prompt..." ▶️ Open file → click play button 🧠 Can auto-detect from description
Example 1 You type /generate-tests — all your test rules pre-loaded ▼

You type /generate-tests then say: "for the payment service"

📋 copilot-instructions.md ← always
⚡ generate-tests.prompt.md ← you typed /generate-tests
"Generate comprehensive tests..."
"Cover: happy path, validation, auth, not-found, edge cases"
"Follow AAA pattern. Name: test_action_scenario_expected"
"Run pytest -v to verify all pass"
▼
✅ RESULT
Copilot generates tests covering ALL scenarios from your prompt — every time, same quality, without you typing the requirements manually.
Example 2 Without the prompt — you get inconsistent results ▼

You just ask: "Write tests for the payment service" (no /prompt)

⚠️ RESULT
Generic tests. Maybe 2-3 cases. Might miss auth tests, validation tests, edge cases. No consistent naming. You have to specify everything EVERY TIME.
Key Concept Skill vs Prompt — both show after typing / — what's the difference? ▼
🍳
/deploy-staging (SKILL)
  • SKILL.md + scripts/ + references/
  • Multi-step procedure with bundled assets
  • "A full recipe with ingredients in the box"
  • Walks you through steps one by one
⚡
/generate-tests (PROMPT)
  • Just one .prompt.md file
  • Single focused task, no bundled files
  • "A speed-dial — press and it does the thing"
  • One-shot generation

Section 06

hooks/*.json

The robot guard that runs whether you want it to or not

🤖
Think of it as: A robot guard standing at the door. Every time Copilot edits a file, the robot runs a linter. Every time Copilot wants to run a command, the robot shows a safety warning. It doesn't think. It doesn't suggest. It doesn't ask. It just runs. 100% of the time. No AI involved.
🔄 Runs automatically on lifecycle events 🚫 You CANNOT skip it ⚙️ Deterministic — not AI, just code
📝
PostToolUse — After an action
  • Fires AFTER Copilot edits a file or creates a file
  • Example: Auto-run ruff check --fix after every edit
  • Guarantees code is formatted — every single time
  • No AI decision — it's a shell command, it just runs
🛡️
PreToolUse — Before an action
  • Fires BEFORE Copilot runs a terminal command
  • Can block dangerous operations
  • Example: Safety warning before any execute action
  • Can enforce security policies, require approval
Critical Distinction Instructions vs Hooks — The most important concept to understand ▼
📋
Instruction says:

"Always format code with ruff"

→ Copilot MIGHT format. It's guidance. ~90% of the time.

Because instructions are processed by the AI model — probabilistic, not guaranteed.

🤖
Hook does:

ruff check --fix after every edit

→ ruff WILL run. It's code. 100% of the time. No AI involved.

Because hooks are shell commands — deterministic, guaranteed, every time.

The Full Picture

What Happens When You Type in Chat

Every step, in order — from your message to the final output

💬

You type something in chat

Your message enters the pipeline. Before ANY processing, Copilot gathers context from your project.

📋

copilot-instructions.md loads

ALWAYS. You did nothing. It just loads. Every time. No exceptions.

📚

Matching *.instructions.md files load

If you have a .py file open → python.instructions.md loads. If it's a test file → testing.instructions.md also loads. You did nothing — auto.

👨‍⚕️

Was an agent selected?

YES → That agent's .md loads with its tool restrictions and persona.
NO → Default agent (all tools, no specialization).

🍳

Did you type /something?

YES → That skill or prompt loads.
NO → Copilot checks descriptions of all skills/prompts and may auto-load one if keywords match.

🧠

LLM generates response

All loaded context + your message → sent to the AI model → generates code or answer.

🤖

Hooks fire automatically

Did Copilot edit a file? → post-edit-lint.json fires (auto-format).
Did Copilot run a command? → pre-execute-warning.json fired before it ran.
